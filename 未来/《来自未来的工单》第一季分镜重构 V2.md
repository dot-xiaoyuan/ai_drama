# 《来自未来的工单》第一季分镜重构 V2

## 一、先修改整个项目最核心的一条规则

旧规则：

> 一个 5 秒镜头 = 一个剧情信息。

取消。

新规则：

> **一个 5 秒生成片段 = 一个连续视觉动作。**
>
> **一个剧情信息可以跨 2～3 个镜头完成。**

例如旧版本：

1. 男主办公室收到任务
2. 手机显示买矿泉水
3. 男主来到售货机
4. 买水
5. 显示未来 +1

每个镜头都像 PPT 翻页。

新版应该变成：

1. 手机震动 → 男主拿起手机
2. 承接拿手机动作 → 看任务 → 抬眼
3. 承接他的视线 → 脚步进入画面 → 镜头往上带出售货机
4. 手伸向按钮 → 饮料掉落
5. 承接饮料掉落声 → 男主拿着水看手机 → 表情变化

剧情没有少。

但镜头之间有了“连接”。

# 二、以后 Agent 必须给每两个镜头设计转场关系

每个 Shot 配置新增：

```json
{
  "transition_in": "",
  "transition_out": "",
  "continuity_anchor": ""
}
```

`continuity_anchor` 是前后镜头共同存在的视觉或声音元素。

只能优先从以下方式选择。

### 1. 动作承接

Shot A：

男主抬起手机。

切镜。

Shot B：

从另一个角度继续抬手机。

这是最自然的一类。

---

### 2. 视线承接

Shot A：

男主突然抬头看向右侧。

切镜。

Shot B：

直接出现他看到的售货机。

观众自然会理解：

**这是他的视线。**

---

### 3. 物体承接

Shot A：

手机占满画面。

切镜。

Shot B：

仍然以手机作为前景，但景别变了。

或者：

Shot A：

矿泉水从机器落下。

Shot B：

男主手中的矿泉水。

---

### 4. 运动方向承接

Shot A：

人物从左向右离开。

Shot B：

脚从画面左侧进入，继续向右走。

不能上一镜向右走，下一镜突然向左。

---

### 5. 镜头运动承接

例如：

Shot A：

镜头缓慢向下移动到手机。

Shot B：

从手机开始，缓慢向上移动到脸。

这两个镜头连起来会非常自然。

---

### 6. 声音桥

这个非常重要。

下一镜的声音可以提前进入。

例如：

办公室。

男主看完“买矿泉水”。

还没有切镜。

已经先听到：

**自动售货机“咚”的掉落声。**

然后切：

售货机。

或者：

上一镜最后 0.3 秒提前出现手机震动声。

下一镜才看到手机。

这就是 J-Cut。

反过来：

上一镜售货机掉水。

已经切到男主脸。

但：

“咚——”

声音还延续。

这是 L-Cut。

以后 Agent 必须大量使用。

---

# 三、生成 5 秒 ≠ 使用 5 秒

这是后续 Agent 必须知道的。

例如生成：

```text
EP01_S03.mp4
duration = 5s
```

实际剪辑可能只使用：

```text
00:00.7 - 00:04.1
```

即：

3.4 秒。

因为 AI 视频最容易出问题的地方经常是：

**刚开始 0.5 秒和最后 0.5 秒。**

所以：

每条生成素材要留：

**前后 Handle。**

原则：

> 生成 5 秒，目标有效素材 3～4.2 秒。

一集 5 个 AI 视频素材：

虽然原始素材：

25 秒。

最终成片可能：

18～23 秒。

这是正常的。

# 五、这样 EP01 的观看感觉完全不同

虽然还是：

**5 个 AI 视频。**

但是观众感受到的是：

手机亮起  
→ 手机被拿起  
→ 男主看手机  
→ 男主看向出口  
→ 人已经在走  
→ 看到售货机  
→ 按按钮  
→ 水掉下来  
→ 水已经在手上  
→ 手机到账  
→ 男主发现异常

这是：

**一个连续过程。**

而不是：

办公室。

手机。

啪。

售货机。

啪。

办公室。

# 七、以后 Agent 写分镜必须通过一个检查

任何相邻两个 Shot：

必须能回答：

> **“我为什么会从这个镜头切到下一个镜头？”**

合格答案例如：

- 因为人物正在完成同一个动作
- 因为人物看向那个方向
- 因为声音把两个场景连接起来
- 因为相同物体连接两个画面
- 因为镜头运动方向一致
- 因为下一镜是上一镜看到的东西

不合格答案：

> “因为剧情到下一段了。”

如果只能这么回答：

**重新设计镜头。**

# 八、一个非常重要的 Agent Prompt 规则

以后不要写：

> 男主看手机，看到信息后震惊，然后走出办公室。

而要写：

> 男主保持站立，只低头查看手机。眉头轻微收紧，随后缓慢抬起视线看向画面右侧。镜头保持稳定，动作自然克制。结尾保持男主看向右侧的姿态，为下一镜视线匹配提供剪辑点。

也就是说：

**Prompt 不只是描述这 5 秒发生什么。**

还必须告诉视频模型：

> **这 5 秒最后停在哪里。**

因为：

**Shot 尾帧，本质上就是下一个 Shot 的起点。**

# 九、新增 Agent 核心约束

每次生成 Shot 之前必须记录：

```json
{
  "opening_state": "",
  "main_action": "",
  "ending_state": "",
  "next_shot_bridge": ""
}
```

例如：

```json
{
  "opening_state": "hero looks at phone",
  "main_action": "hero slowly raises his gaze",
  "ending_state": "hero looks toward frame right",
  "next_shot_bridge": "cut to object in his eyeline"
}
```

这四项以后应该和：

角色一致性

同等重要。

# 十、最终目标

以后我们不是让 Agent 做：

**五个好看的 5 秒视频。**

而是做：

**一个连续的 20 秒场景，被拆成五段生成。**

这两个思路看起来差不多，

实际生成出来的东西会完全不一样。
